# hp_remote

Android 기기의 화면을 PC 웹 브라우저에서 보고, 터치·스와이프·키 입력으로 원격 조작하는 프로그램입니다.

## 구조

```
android/   Android 앱 (원격 조작을 당하는 폰에 설치)
server/    Node.js 중계 서버 (폰 <-> 웹 컨트롤러 WebSocket 릴레이 + 웹 페이지 서빙)
web/       PC 브라우저용 컨트롤러 UI (server가 정적 파일로 서빙)
```

### 동작 방식

1. `server`를 PC(또는 두 기기가 접근 가능한 서버)에서 실행합니다.
2. Android 앱을 설치하고 실행하면 6자리 페어링 코드가 표시됩니다. 앱에 서버 주소(`ws://<서버IP>:8080/ws`)를 입력하고 "화면 공유 시작"을 누르면:
   - 시스템이 화면 캡처 동의 다이얼로그를 띄웁니다 (매번 필요, 우회 불가 — Android 정책).
   - 동의하면 `MediaProjection`으로 화면을 캡처해 JPEG로 인코딩, WebSocket으로 서버에 전송합니다.
3. 터치 입력을 받으려면 앱에서 "접근성 설정 열기" 버튼으로 이동해 hp_remote의 접근성 서비스를 수동으로 켜야 합니다 (역시 자동화 불가 — Android 정책).
4. PC 브라우저에서 `http://<서버IP>:8080` 접속 후 같은 6자리 코드를 입력하면 화면이 실시간으로 보이고, 클릭/드래그가 탭/스와이프로, 하단 입력창의 텍스트가 포커스된 입력란으로 전달됩니다.

서버는 코드로 device 1개 : controller 1개를 페어링만 할 뿐 프레임/명령의 내용은 그대로 중계(relay)하기만 합니다.

## 실행 방법

### 1. 중계 서버

```bash
cd server
npm install
npm start   # http://localhost:8080
```

같은 Wi-Fi에 있는 폰과 PC가 접속할 수 있도록 서버를 띄운 PC의 사설 IP(예: `192.168.0.10`)를 확인해두세요. 방화벽에서 8080 포트를 열어야 할 수 있습니다.

### 2. Android 앱

`android/` 폴더를 Android Studio(Hedgehog 이상)에서 "Open"으로 엽니다. Gradle Wrapper가 없으므로 최초 오픈 시 Android Studio가 자동으로 wrapper를 생성해줍니다 (또는 로컬에 Gradle 8.x가 있다면 `gradle wrapper` 실행).

- `minSdk 26`, `targetSdk 34`
- 실제 기기에 빌드 후 설치 (에뮬레이터도 화면 캡처는 되지만 실기기 테스트 권장)
- 앱 실행 → 서버 주소 입력 → 화면 공유 시작 → 접근성 서비스 켜기

### 3. 웹 컨트롤러

PC 브라우저에서 `http://<서버IP>:8080` 접속 → 폰 앱에 표시된 6자리 코드 입력.

## 보안/사용상 주의사항

이 프로젝트는 **본인 소유 기기를 본인이 원격 조작**하거나, 상대방의 명시적 동의 하에 원격 지원을 하는 용도로 설계되었습니다.

- 화면 캡처(MediaProjection)와 접근성 서비스 권한은 Android 정책상 매번/최초 1회 **기기에서 직접 동의**해야만 켜집니다. 몰래 켤 수 없습니다.
- 중계 서버에는 별도 인증이 없고 6자리 코드만으로 페어링합니다. **신뢰할 수 없는 네트워크(공용 와이파이 등)에 서버를 그대로 노출하지 마세요.** 실제 운영 시에는 다음을 추가하는 것을 권장합니다:
  - 서버 앞단에 TLS(HTTPS/WSS) 적용
  - 코드에 만료 시간(TTL) 부여, 페어링 성공 시 즉시 코드 폐기(현재 미구현)
  - 서버 접근 자체를 VPN이나 IP allowlist로 제한
- 화면 스트리밍은 WebSocket + JPEG 프레임 방식으로, 지연시간이 WebRTC 대비 다소 높습니다(수백 ms 대). 프레임 전송 주기는 `ScreenCaptureService.MIN_FRAME_INTERVAL_MS`(기본 150ms)로 조절할 수 있습니다.
- 텍스트 입력(`text` 명령)은 현재 포커스된 입력란이 있어야 동작합니다(접근성 API의 `ACTION_SET_TEXT` 사용).

## 알려진 한계 (MVP)

- 서버에 인증/암호화가 없음 (위 보안 항목 참고)
- 한 코드당 device/controller 각 1개만 페어링 가능 (여러 기기 동시 관리 미지원)
- 화면 방향 전환(가로/세로) 시 해상도 갱신은 되지만 컨트롤러 쪽 레이아웃 전환은 테스트 필요
- 알림, 클립보드 동기화, 파일 전송 등은 미구현

# hp_remote

Android 기기의 화면을 PC 웹 브라우저에서 보고, 터치·스와이프·키 입력으로 원격 조작하는 프로그램입니다. 같은 저장소에 폰 데이터 복제 기능(hp_clone)도 함께 들어 있습니다.

> 저장소 이름을 `hp_control`로 바꾸는 건 GitHub 저장소 설정(Settings → Repository name)에서 직접 해야 합니다 - 세션 도구로는 저장소 이름을 바꿀 수 없습니다. 코드 쪽 모듈/앱 이름은 이미 `hp_control` 기준으로 맞춰뒀습니다.

## 구조

기능(화면·로직)과 앱 껍데기를 분리한 멀티모듈 구조입니다. `feature-*`는 라이브러리 모듈이라 그 자체로는 설치할 수 없고, `app-*` 중 하나에 포함되어야 apk가 나옵니다.

```
android/
├── feature-remote/   화면 미러링/원격 제어 화면·로직 (라이브러리, 패키지 com.hpremote.agent)
├── feature-clone/    폰 데이터 복제 화면·로직 (라이브러리, 패키지 com.hpremote.clone)
├── app-remote/       hp_remote Agent 단독 apk (feature-remote만 포함)
├── app-clone/        hp_remote 폰 복제 단독 apk (feature-clone만 포함)
├── app-control/      hp_control 통합 apk (feature-remote + feature-clone, 홈 화면에서 선택)
└── keystore/         3개 app-* 모듈이 공유하는 디버그 서명 키
server/               Node.js 중계 서버 (폰 <-> 웹 컨트롤러 WebSocket 릴레이 + hp_clone 인터넷 경유 릴레이)
server/public/        PC 브라우저용 컨트롤러 UI (server가 정적 파일로 서빙)
```

`core` 모듈은 일부러 만들지 않았습니다 - 두 기능이 지금 실제로 공유하는 코드가 없어서(통신 프로토콜부터 다름) 빈 모듈만 두는 게 의미가 없기 때문입니다. 나중에 실제로 공유할 코드가 생기면 그때 뽑아내면 됩니다.

세 가지 설치 옵션이 있습니다:
- **원격 제어만 필요** → `app-remote` 설치 (applicationId `com.hpremote.agent`)
- **폰 복제만 필요** → `app-clone` 설치 (applicationId `com.hpremote.clone`)
- **둘 다 한 앱으로** → `app-control` 설치 (applicationId `com.hpremote.control`) - 실행하면 첫 화면에서 "원격 제어" / "데이터 복제" 중 선택하고, 그 다음은 각 기능 화면(복제라면 기존처럼 보내기/받기 → 연결 방식 선택)으로 그대로 이어집니다.

### 동작 방식

1. `server`를 PC(또는 두 기기가 접근 가능한 서버)에서 실행합니다.
2. Android 앱을 설치하고 실행하면 6자리 페어링 코드가 표시됩니다. 앱에 서버 주소(`ws://<서버IP>:8080/ws`)를 입력하고 "화면 공유 시작"을 누르면:
   - 시스템이 화면 캡처 동의 다이얼로그를 띄웁니다 (매번 필요, 우회 불가 — Android 정책).
   - 동의하면 `MediaProjection`으로 화면을 캡처해 JPEG로 인코딩, WebSocket으로 서버에 전송합니다.
3. 터치 입력을 받으려면 앱에서 "접근성 설정 열기" 버튼으로 이동해 hp_remote의 접근성 서비스를 수동으로 켜야 합니다 (역시 자동화 불가 — Android 정책).
4. PC 브라우저에서 `http://<서버IP>:8080` 접속 후 같은 6자리 코드를 입력하면 화면이 실시간으로 보이고, 클릭/드래그가 탭/스와이프로, 하단 입력창의 텍스트가 포커스된 입력란으로 전달됩니다.

서버는 코드로 device 1개 : controller 1개를 페어링만 할 뿐 프레임/명령의 내용은 그대로 중계(relay)하기만 합니다.

## 실행 방법

### 1. 중계 서버

```bash
cd server
npm install
npm start   # http://localhost:8080
```

같은 Wi-Fi에 있는 폰과 PC가 접속할 수 있도록 서버를 띄운 PC의 사설 IP(예: `192.168.0.10`)를 확인해두세요. 방화벽에서 8080 포트를 열어야 할 수 있습니다.

### 2. Android 앱

`android/` 폴더를 Android Studio(Hedgehog 이상)에서 "Open"으로 엽니다. Gradle Wrapper가 없으므로 최초 오픈 시 Android Studio가 자동으로 wrapper를 생성해줍니다 (또는 로컬에 Gradle 8.x가 있다면 `gradle wrapper` 실행).

- `minSdk 26`, `targetSdk 34`
- 실제 기기에 빌드 후 설치 (에뮬레이터도 화면 캡처는 되지만 실기기 테스트 권장)
- 앱 실행 → 서버 주소 입력 → 화면 공유 시작 → 접근성 서비스 켜기

### 3. 웹 컨트롤러

PC 브라우저에서 `http://<서버IP>:8080` 접속 → 폰 앱에 표시된 6자리 코드 입력.

## 보안/사용상 주의사항

이 프로젝트는 **본인 소유 기기를 본인이 원격 조작**하거나, 상대방의 명시적 동의 하에 원격 지원을 하는 용도로 설계되었습니다.

- 화면 캡처(MediaProjection)와 접근성 서비스 권한은 Android 정책상 매번/최초 1회 **기기에서 직접 동의**해야만 켜집니다. 몰래 켤 수 없습니다.
- 중계 서버에는 별도 인증이 없고 6자리 코드만으로 페어링합니다. **신뢰할 수 없는 네트워크(공용 와이파이 등)에 서버를 그대로 노출하지 마세요.** 실제 운영 시에는 다음을 추가하는 것을 권장합니다:
  - 서버 앞단에 TLS(HTTPS/WSS) 적용
  - 코드에 만료 시간(TTL) 부여, 페어링 성공 시 즉시 코드 폐기(현재 미구현)
  - 서버 접근 자체를 VPN이나 IP allowlist로 제한
- 화면 스트리밍은 WebSocket + JPEG 프레임 방식으로, 지연시간이 WebRTC 대비 다소 높습니다(수백 ms 대). 프레임 전송 주기는 `ScreenCaptureService.MIN_FRAME_INTERVAL_MS`(기본 150ms)로 조절할 수 있습니다.
- 텍스트 입력(`text` 명령)은 현재 포커스된 입력란이 있어야 동작합니다(접근성 API의 `ACTION_SET_TEXT` 사용).

## hp_remote 폰 복제 (`android/feature-clone`)

기존 폰의 데이터를 새 폰으로 옮기는 기능입니다. `app-clone`으로 단독 설치하거나, `app-control`로 원격 제어와 한 앱에 합쳐서 설치할 수 있습니다.

- 연결 방식을 먼저 고르고, 그다음 복제할 데이터를 선택합니다. 세 가지 방식 중 선택 가능:
  - **같은 네트워크** — 같은 Wi-Fi 공유기 또는 한쪽 폰의 개인 핫스팟. 서버 없이 직접 TCP(포트 `58642`)로 통신.
  - **Wi-Fi Direct** — 공유기·핫스팟 없이 폰끼리 바로 P2P 연결. 로컬 전송 중 가장 빠르고, 새 폰(받는 쪽)이 자동으로 그룹을 열어두면 보내는 쪽에서 주변 기기를 검색해 선택하기만 하면 됩니다(IP 직접 입력 불필요).
  - **인터넷 경유** — 완전히 다른 네트워크(한쪽이 데이터망)에서도 가능하도록 기존 hp_remote 서버를 통해 중계. 느릴 수 있지만 유일하게 원거리에서도 동작.
  - (검토 후 제외: 블루투스는 사진/동영상 전송엔 너무 느리고, Google Nearby Share는 별도 무거운 SDK가 필요해 제외했습니다.)
- PIN 6자리로 페어링(모든 방식 공통, 인터넷 경유에서는 서버 방 코드로도 재사용).
- 옮길 수 있는 데이터: 설치된 앱 목록, 연락처, 통화 기록, 캘린더, 문자 메시지, 사진, 동영상 - 이 순서(빠른 것부터: 텍스트 레코드 → 큰 바이너리)로 전송됩니다.
- 전송 시작 전에 항목별 예상 소요 시간(대략치)을 보여주고 확인을 받은 뒤 시작하며, 진행 중에는 "N/7 처리 중: 카테고리명" + 현재 항목 진행률 + 전체 진행률 두 개의 진행 바를 표시합니다.
- 문자 메시지를 새 폰에 실제로 쓰려면(단순 조회가 아니라) 안드로이드 정책상 그 순간 "기본 문자 앱"이어야 해서, 받기 시작 시 해당 권한을 요청합니다. 거부해도 나머지 데이터 전송은 계속됩니다.
- **루팅 없이는 옮길 수 없는 것**: 앱 내부 데이터(게임 세이브, 로그인 세션 등), Wi-Fi 비밀번호. 설치된 앱은 목록만 전달되며 새 폰에서 Play 스토어로 각각 재설치해야 합니다. 이는 Android 샌드박스 정책 때문으로, 별도 구현으로 우회할 수 없습니다.
- 사용법: 새 폰에서 앱 실행 → "새 폰으로 데이터 받기" → 연결 방식 선택 → (같은 네트워크면 표시되는 IP/PIN, Wi-Fi Direct/인터넷 경유면 각 방식 안내에 따라) 기존 폰의 "이 폰의 데이터 보내기" 화면에서 같은 방식으로 연결 → 복제할 데이터 선택 → 전송 시작. 전송 중에는 두 폰 모두 앱을 화면에 켜 둔 상태로 유지해야 합니다.

## 알려진 한계 (MVP)

- 서버에 인증/암호화가 없음 (위 보안 항목 참고)
- 한 코드당 device/controller 각 1개만 페어링 가능 (여러 기기 동시 관리 미지원)
- 화면 방향 전환(가로/세로) 시 해상도 갱신은 되지만 컨트롤러 쪽 레이아웃 전환은 테스트 필요
- 알림, 클립보드 동기화, 파일 전송 등은 미구현
